## The original project, in plain language

Detect visible humans (initial target) and supported indoor objects with the
existing pretrained YOLOv3-tiny camera detector. Associate detections with valid
physical 2D LiDAR measurements when the sensors actually observe the same target.
First show labelled observations relative to the robot; later place them on a
room map using trustworthy robot pose and sensor transforms. Evaluate detection,
association, timing and position errors and document limits.

The camera supplies "what"; LiDAR supplies supporting distance/planar geometry,
not an independent object label. Robot pose supplies where the observation
belongs on the map. The remote website is an operator tool supporting this
project, not a replacement for the thesis contribution.

Keep the agreed pretrained model, no custom training/fine-tuning or model swap.
No new SLAM algorithm, autonomous navigation, generic hand/box recognition, 3D
LiDAR mode or proof of physiological life is promised. Human/animal objectives
remain, with person as the first implemented/evaluated case. Camera depth can
help, but does not replace demonstrating the requested physical LiDAR association.
Authoritative scope: `AGREED_PRETRAINED_FUSION_SCOPE_2026-10-14.md`.

Implementation checklist for the next coding stage:

- Preserve default read-only/preview mode. Motor mode must be an explicit
  robot-side opt-in, visibly distinct from rehearsal, disabled after restart.
- Reuse isolated controller input and fresh-source/ownership/readiness checks;
  do not start/stop vendor processes, alter GPSD or change firmware from a web
  request. Keep original vendor files/maps and working image path intact.
- First action: one bounded forward request, initially the unchanged 0.03 m/s /
  0.4 s intent with repeated zero attempts, not a speed/distance guarantee. A click
  must not latch continuous motion, and retries/reconnects must not replay it.
- Later controller behavior should be press-and-hold/release-to-stop, not a
  click-on/click-off latch. Reverse/left/right arcs are additional verified steps,
  not presumed proven by one forward test. Ackermann steering cannot turn in place.
- Enforce request duration/speed/command expiry on the robot backend, not just
  browser timers. Single operator, deliberate enable, current generation/sequence,
  stale-data/connection/feedback refusal, and no automatic resumption.
- Test Stop/release, stale/duplicate/out-of-order requests, missed heartbeat,
  blur/hidden page, lost browser connection, process shutdown, stale graph/odom,
  competing publisher, worker scheduling gaps and no replay with fake clocks/ROS
  before live enablement. Maintain existing viewing/rehearsal regressions.
- Do not present an application heartbeat or zero publication as an independent
  hardware watchdog. A dead/stalled Jetson or broken serial link may prevent zeros.
  Do not deliberately disconnect communications during a moving floor test.

## Return to mapping: next concrete checkpoint

After operator work is stable, keep the robot stationary and check the physical
scan stream plus camera calibration, sensor frame connectivity and timing. Reuse
the focused `fusion_check_...txt` procedure in `LAB_PLAN_2026-10-15.md` only after
checking its listed sensor launches are not already running and helper file is
present. The old document's initial-network/alternative priority status is
historical; use it for the scoped sensor/report procedure, not its old schedule.

First fusion output is a debugging overlay of projected LiDAR points on the
camera image, then defensible person/scan association in robot-relative space.
An existing TF is not proof of correct calibration. Do not invent identity TF or
copy nominal URDF mounts as measured calibration. The low scan plane can hit
legs but miss seats/tabletops; wall returns inside a detection box are not
automatically part of the detected person. Leave unsupported positions unknown.

Only after time/geometry/association checks and valid map-frame robot pose do we
add a separate labelled observation/marker layer to an existing validated 2D
occupancy map. Moving people should expire/update rather than become permanent
static obstacles. Base odometry now arriving does not alone establish accurate
global map pose. Preserve existing maps; vendor mapping launchers may delete a
database and must be inspected before reuse. No mapping/navigation launch today
merely to make a sensor transform appear.
